# M4 报告：把 West Window 的八款游戏装进同一份契约

- **来源**：SerenQi/rain-go（西窗 / West Window），commit `06e4b7515da709d3f5860ac37c4c3bddd00fce42`，MIT，`Copyright (c) 2026 SerenQi`
- **起点**：`9b0bda3`（M3 收尾 + 生产发布，10 款游戏）
- **终点**：16 款游戏，全部跑在同一套 `GamePlugin` 契约上
- **阶段文档**：`M4-AUDIT.md`（审计）、`M4-DESIGN.md`（设计）、`M4-MIGRATION-MATRIX.md`（迁移矩阵）、`M4.1`–`M4.5` 阶段报告

## 1. 一句话结论

**M4 只改了一次公共契约。** 八款新游戏里，七款完全用 M3 已有的钩子接完；唯一必须动契约的是斗地主——两个农民同时获胜，而 `winnerTeam` 当时只允许 `"red" | "blue"`。改动是把两个字段的类型放宽成 `string`，旧房间、旧归档、旧 MCP 客户端都不受影响。

其余"看起来要加能力"的场景，最后都落在既有钩子上：

| 场景 | 用的是什么 |
| --- | --- |
| 一回合内多个决策（大富翁 roll→buy→build→end） | 插件自己保持 `currentPlayerId`，平台从不强制换手 |
| 两个座位同时决策（围棋数子） | `mayActNow` 放宽 + `currentPlayerId` 置空（M3 就有的钩子，围棋是第二个使用者） |
| 只有观看者能看到的列表（大富翁可建房地、围棋合法点） | `projectState` 按观看者计算后下发 |
| 隐藏牌堆/手牌/命运牌序 | `projectState` 置 `undefined`，三个出口共用同一份投影 |
| 结构化的复合动作（出牌、叫分、买地、落子） | `GAME_ACTIONS` 的 `data` 字段声明，MCP 自动发现 |

## 3. 每个游戏长什么样

```text
apps/workers/src/games/<id>/rules.ts     纯函数：几何、合法性、胜负、计分
apps/workers/src/games/<id>/plugin.ts    GamePlugin：状态、行动、投影、效果
apps/workers/src/games/<id>/agent.ts     紧凑决策态
apps/workers/src/durable-objects/<X>Room.ts   ~110 行平台胶水
apps/web/src/game-ui/<X>.tsx             棋盘
```

| 游戏 | rules | plugin | agent | 前端 | 备注 |
| --- | --- | --- | --- | --- | --- |
| 五子棋 | 146 | 211 | 62 | 217 | 最薄的一款 |
| 飞行棋 | 208 + 92 | 415 | 134 | 654 | 自带 `board.ts`（52 格环） |
| 跑得快 | 85 | 422 | 123 | 189 | 与斗地主共用 `cards/`（657 行） |
| 斗地主 | 99 | 583 | 143 | 250 | 叫分 + 出牌两阶段 |
| 大富翁 | 185 + 191 | 881 | 90 | 357 | 五阶段 + 静态棋盘 |
| 国际象棋 | 645 | 404 | 102 | 294 | 走法生成占了大头 |
| 中国象棋 | 513 | 366 | 99 | 268 | 记谱占 90 行 |
| 围棋 | 330 | 601 | 118 | 216 | 插件最大：两阶段 + 数子 |

规律很清楚：**规则越"几何"，`rules.ts` 越厚；流程越"分支"，`plugin.ts` 越厚。** 围棋的规则本身不复杂（气、提子、劫），但两个阶段、双方确认、死子标记把插件推到 601 行。反过来国际象棋的流程是一条直线，645 行几乎全在走法生成上。

## 4. 三次返工，都是"看起来对"

### 双王的牌号撞了黑桃 J

跑得快的双王最初写作 `SJ` / `BJ`，而 ♠J 的牌号正是 `SJ`。解析器把黑桃 J 认成小王，一手正常的牌被判成"你手上没有小王"。MCP 全链路第一次跑就撞上。现在王的任何表示都不带花色字母：id `j1`/`j2`，标签 `J1`/`J2`。

### 骰子五点画成了六点

飞行棋的点数用 pip 坐标画，五点的坐标写错，和六点长得一样。这种错误单测抓不到——它只在人看的时候才暴露，最后靠截图比对发现。

### 中国象棋画反了

`rank 0` 直接映射到 `y(0)`，于是红方底线被画在了上方。正确的映射是 `y = flipped ? y(rank) : y(RANKS - 1 - rank)`，而且九宫的对角线要跟着一起镜像——第一版只改了棋子没改九宫，出现了"棋子在下面、九宫在上面"的错位。

三次的共同点：**它们都通过了类型检查和单元测试**。所以四视口截图和人工核对不能省。

## 6. M4.6 全量回归

**全量浏览器套件 602 项（4 并行，40.9 分钟）：577 passed / 13 failed / 12 skipped。** 13 项失败逐个查完，结论是"1 个真回归 + 12 个环境问题"：

| 失败项 | 归因 | 处置 |
| --- | --- | --- |
| `preview-navigation.spec.ts` all internal preview links stay in previews | **真回归**：三款新游戏的链接没进预览重写表，`/chess`、`/xiangqi`、`/go` 直接跳出了预览 | `PreviewNavigation.astro` 的 games 数组补上三个 id，复跑 2/2 通过 |
| `account` ×5、`avatar`、`hero`、`public` ×3 共 10 项 | 本地没有 worker API（`/api/v1/auth/users/me` 连接被拒） | 在 6787 起本地 worker 后复跑这 6 个 spec 共 130 项，128 项通过，剩下两项见下两行 |
| `complete-preview.spec.ts` landing and public preview 1440 | 30 秒总预算含 axe 扫描，机器负载下超时 | 单 worker 复跑通过 |
| `end-flow.spec.ts` Pokémon finishes the final attack before showing rewatch | 终局动画窗口只有 650ms，短于本机断言间的延迟 | 本机始终复现；M4 未改 `MatchDesk` 的这条路径，宝可梦与 Poker 的源码也没动过，判定为环境时序问题 |

也就是说：**除了一项时序敏感的动画用例，套件里没有因这次移植产生的回归**；那一项与本里程碑改动的文件没有交集。

四款新游戏（国象、中象、围棋，加上 M4.4 的大富翁）在四个视口下分别单独跑过布局断言，全部通过。

## 7. 没做的事

| 项 | 原因 |
| --- | --- |
| 机器人（`*Bot`） | 平台不托管 bot；需要时走独立 Agent Runner |
| 中国象棋长将/长捉 | 需要循环内将军判定；60 分钟时钟已兜底 |
| 围棋 13 路 / 19 路 | 平台还没有房间配置项承载；规则层已按 `size` 写，改一行常量即可 |
| 围棋聊天/改名（`say` / `rename`） | 平台有独立聊天通道 |
| 大富翁拍卖/抵押 | 来源也没有拍卖；抵押被"半价卖房卖地"覆盖 |
| 斗地主 1/3/6 局赛制 | 平台一次 match 只有一个结局 |

## 8. 下一步

M5 应该回答的不是"再加几款游戏"，而是**这些游戏在真实对局里好不好用**：agent 走一手要几秒、决策态够不够读懂、观战和回放的体验如何。八款新游戏现在都有 `legal` 与紧凑决策态，但没有一局是真人真模型跑完的——这是 M4 交付里最大的空白。

具体建议：

1. 用 `examples/` 里的 agent runner 跑 20 局混合对局，记录每手的决策时延与非法动作率。
2. 把非法动作率高的游戏（预计是围棋和斗地主）的决策态再压一轮。
3. 围棋的房间配置项（棋盘尺寸）值得单独做，因为 19 路和 9 路是两种游戏体验。

**2026-11-01 已上生产**：`games.xsrc.in` 从 8 款变 16 款，D1 迁移 `0054`–`0061` 全部应用，Worker `6ee80c71`、Pages `e2f28ce3`。发布时补了两处：MCP 版本号 `0.8.0 → 0.9.0`（原来在两个文件里硬编码，现在收成 `src/mcp/version.ts` 一个常量），以及 `llms.txt` 只列了 7 款游戏（连 M3 的 Contexto 都漏着），补到 16 款。

完整步骤、核对结果、回滚口径与"没验到的"见 [`M4-RELEASE.md`](M4-RELEASE.md)。一句话概括风险：**八款新游戏里没有一款在线上真开过一局**——房间创建要 OAuth 人工授权，本地 16 条 MCP 全链路覆盖了同一条路径，但不能替代生产环境的那一下。

那个空白当天就收了账：上线后新游戏停在等待大厅，原因是前端手写的 zod 契约没跟上 `seat0` 与字符串棋盘，`Room.tsx` 又把被拒的帧静默丢弃。修复与新增的跨端契约门禁见 [`M4.6.1-REPORT.md`](M4.6.1-REPORT.md)。
