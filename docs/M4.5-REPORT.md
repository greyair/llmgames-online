## 1. 同一件事，三种棋盘

三款棋都是「两人轮流落子，棋盘全公开」，但棋盘形状完全不同，所以**没有抽公共棋盘层**：

| | 表示 | 索引 | 谁先走 |
| --- | --- | --- | --- |
| 国际象棋 | 64 字符的字符串 | FEN 序，0 = a8，63 = h1 | 白（座位 1） |
| 中国象棋 | 90 个字符串的数组 | `rank * 9 + file`，rank 0 = 红方底线 | 红（座位 1） |
| 围棋 | 81 个数字的数组 | `row * 9 + col`，row 0 = 顶部 | 黑（座位 1） |

国际象棋用字符串是因为一整盘棋就是一句话，前端 `board.slice()` 就能取行；两款象棋子必须逐个查，用数组更直接；围棋需要 0/1/2 三态，用数字最省。**共用的是约定而不是代码**：座位 1 永远是先手方，`legal` 永远是"现在能发什么"，前端永远只画不发判断。

## 2. 国际象棋

```text
apps/workers/src/games/chess/rules.ts    330 行  走法、易位、吃过路兵、升变、和棋
apps/workers/src/games/chess/plugin.ts   420 行  状态、投影、超时、紧凑决策态
apps/workers/src/games/chess/agent.ts    120 行
apps/web/src/game-ui/Chess.tsx           350 行
```

**验证走法生成器的唯一可靠办法是 perft**。开局深度 2 = 400、深度 3 = 8902，Kiwipete 局面深度 1 = 48、深度 2 = 2039——这四个数字直接写进测试。少一个吃过路兵、错一次易位、漏一个牵制，深度 3 就会对不上。

三条容易写错的规则，都有单独用例：

1. **易位要检查经过的格**。王不能从被攻击的格出发、不能经过被攻击的格、不能落在被攻击的格——三处都要查，而车只需查"没动过"和"中间是空的"。
2. **吃过路兵被吃掉的兵不在目标格上**。`boardAfter` 里删的是 `(from & ~7) | (to & 7)`，即"起点那一行、终点那一列"。
3. **重复局面键里，吃过路兵格只在真能吃时才计入**。否则两个实际等价的局面会被算成不同，三次重复永远判不出来。

**超时判负**，不是"跳过"。棋类没有"过"这个动作，硬造一个"替玩家走一步"比判负更糟——玩家会看到自己被系统走出一步臭棋。`onTurnTimeout` 直接把胜利给对手，理由 `timeout`。

投影只藏 `history`（重复局面键），其余全公开。

## 3. 中国象棋

```text
apps/workers/src/games/xiangqi/rules.ts    500 行  走法、将帅照面、传统记谱
apps/workers/src/games/xiangqi/plugin.ts   470 行
apps/workers/src/games/xiangqi/agent.ts    100 行
apps/web/src/game-ui/Xiangqi.tsx           300 行
```

四类特殊规则，一类一个用例：

| 规则 | 要点 |
| --- | --- |
| 蹩马腿 | 先横竖一格再斜出，**那一格有子就走不了**——两个落点一起作废 |
| 塞象眼 | 斜走两格，中间那格有子就走不了，且永远不过河 |
| 炮架 | 不吃子时同车；吃子**必须恰好隔一个子**，颜色不限 |
| 白脸将 | 双方将帅不能在同一直线照面，等于给"帅"加了一条横向的远程攻击 |

**记谱**是这一关最花心思的部分，也是唯一"看起来像功能、其实是文案"的代码：`炮二平五`、`馬8進7`、`前車進一`。红方用中文数字、从自己右手边数，黑方用阿拉伯数字；同一条线上有两枚同种棋子时用「前/後」，三枚用「前中後」，四个以上用序号；两个纵线都有两枚以上兵时改用纵线名。这套规则搬到 `rules.ts` 里 60 行，测试里锁了三条（`h2e2` = 炮二平五、`b2e2` = 炮八平五、`h9g7` = 馬8進7）。

**和棋**：连续 120 个半回合无吃子，或双方都没有车马炮兵。来源里的长将/长捉**没有实现**，因为它需要一套"循环内是否在将军"的判定，而平台的 60 分钟时钟已经兜住了无限循环。

**无路可走即负**，无论是否被将军（将死 / 困毙）。这一点和国象不同：国象的逼和是和棋。

## 4. 围棋

```text
apps/workers/src/games/go/rules.ts    430 行  气、提子、禁入、劫、数子、GTP 坐标
apps/workers/src/games/go/plugin.ts   560 行  两阶段状态机、投影、超时
apps/workers/src/games/go/agent.ts    110 行
apps/web/src/game-ui/Go.tsx           290 行
```

围棋是唯一有**两个决策阶段**的一款：`playing` → 两停 → `scoring` → 双方确认 → `ended`。

阶段切换全部有测试：

- **两停进数子**：`passes` 计数到 2 就切 `scoring`，清空死子标记与确认。
- **标记死子清空确认**：任何一次 `mark_dead` 都把 `accepted` 清空——否则一方改完标记另一方还"确认"着。
- **双方确认才结算**：`accepted.length === 2` 时用 `areaScore` 算出结果并终局。
- **`resume_play` 退回对局**：清死子标记、清确认、`passes` 归零、回合交还给该走的一方。

**数子阶段没有单一回合归属**。这是全平台第一个这样的局面，所以：

| 位置 | 处理 |
| --- | --- |
| `mayActNow` | `scoring` 阶段两个座位都返回 true |
| `turnState.currentPlayerId` | 进数子时置 `null`，`resume` 时恢复 |
| `onTurnTimeout` | 对局阶段=停一手，数子阶段=确认（来源的 bot 也是这么做的） |

**投影带 `legal` 却不是因为前端懒**。围棋的合法性依赖 superko 历史——棋盘上看不出"这一手会不会重现之前的局面"，所以合法点必须服务端算。`projectState` 里算好 81 个点（多数情况下除去已有子就是全部），随视图下发；`agentDecision` 直接读它，不重复计算。

**棋盘尺寸固定 9 路**。来源把 9/13/19 做成选项，平台目前没有房间配置项承载它。`rules.ts` 里所有函数都按 `size` 参数写，插件里只有一个 `GO_DEFAULT_SIZE = 9`——加配置项时改一行。这条记在 §6。

## 5. 前端

三块棋盘都**只画不发判断**：

- **国象**：`legal` 是 UCI 列表，前端过滤出"从这枚棋子出发能到哪"。点击格子→选中→点提示格→发 `move`。升变时弹四个按钮。黑方视角整块棋盘 180° 翻转（`63 - index`）。
- **中象**：`legal` 是 ICCS，前端只画圆点。棋盘是 SVG 线框：9 条纵线、10 条横线、楚河汉界断开、两个九宫对角线。**方向是这次唯一的返工**：第一版把红方画在了上方，因为 `rank 0` 直接映射到了 `y(0)`；正确做法是红方底线在下，所以 `y = flipped ? y(rank) : y(RANKS - 1 - rank)`，九宫的对角线也要跟着镜像。
- **围棋**：`legal` 是 GTP 名单。**第一版在每个空点都画了合法点**，75 个绿点糊满棋盘——去掉，只保留悬停虚影和"可点"光标。数子阶段点死子会打叉并变淡。

三款的坐标标注也各不相同，各自跟随棋盘：国象 a–h / 1–8、中象不标（传统棋盘本来没有）、围棋 GTP 的 A–J 跳 I。

## 6. 与来源的差异

| 项 | 来源 | 这里 | 原因 |
| --- | --- | --- | --- |
| 输入 | 文本（"e2e4"、"h2e2"、"D4"） | 结构化 `{from,to}` / `{point}`，也可只发一个字符串 | 平台要求可校验、可发现 |
| 国象超时 | 无 | 判负 | 棋类没有"过"，替玩家走棋更糟 |
| 中象长将/长捉 | 不判负 | 不判负（与来源一致） | 需要额外循环判定；时钟兜底 |
| 中象 120 步 | 判和 | 判和 | — |
| 围棋尺寸 | 9/13/19 选项 | 固定 9 路 | 平台还没有房间配置项；规则层已按 size 写 |
| 围棋贴目 | 7.5 | 7.5 | — |
| 围棋聊天/改名 | `say` / `rename` | 未移植 | 平台有独立聊天通道 |
| 机器人 | chessBot / xiangqiBot / goBot | 未移植 | 平台不托管 bot |
| 记谱 | 国象 SAN、中象传统记谱 | 同 | 用于走子记录与界面提示 |
