## 1. 棋盘：24 格环

来源的地图是环形的，24 格、四角是功能格，16 块地分成 8 组、每组 2 块——只有集齐一组才能盖房。地契名字沿用了来源的中文意象（巴山、秋池、西窗、剪烛……），右上角用「壹」到「捌」标组别。

起始现金 1500，过起点 +200，出狱金 50，房屋上限 3 层，修房卡每层 25。棋盘是**静态数据，不进状态**：持久化的房间只存 `owners` / `houses` / `cash`，重启时不会带一份规则书的副本。

租金有一条容易写漏的规则：整组在手且**一块房都没盖**时，基础租金翻倍。所以垄断一组立刻就有回报，而不是非得盖房——这条有测试。

## 2. 破产的次序

这是移植里唯一需要反复读的部分。`charge()` 先扣钱，不够就 `raiseCash()`：

1. 按地价从便宜到贵，**先卖房**：归还 `floor(houseCost × 层数 / 2)`；
2. 还不够，**再卖地**：归还 `floor(地价 / 2)`，房子一并清空；
3. 走完这两轮仍为负，才判破产，全部资产收归银行、该座位出局。

顺序的意义是"能付就一定付"——半价卖房比半价卖地便宜，先卖房对玩家更有利。测试里有一条专门验证这个次序：付 50 之后再踩 100 的税格，先卖掉房子而不是直接整块地交出去。

租金的收款人处理也在 `settle()` 里：**收款发生在破产判定之后**。破产时钱不转给债主，而是资产回银行——避免了"最后一笔钱到底归谁"的歧义。

## 3. 骰子、监狱、命运

骰子在 `applyAction` 里用平台 CSPRNG 摇，结果写进 state，所以 `requestId` 重放和 DO 重启都是幂等的。来源的 `riggedDice` 是测试后门，**没有带进生产状态**（审计报告点名过这一点）。

| 情况 | 处理 |
| --- | --- |
| 掷出对子 | `doubles += 1`，本回合结束后**再掷一次**，phase 回到 `roll` |
| 第三次对子 | 直接进牢，`position = 6`，回合结束 |
| 在牢里掷出对子 | 出狱，并按这一掷正常移动 |
| 在牢里没掷出对子 | `jailTurns += 1`；前两次只是等待，phase 到 `end` |
| 第三次没掷出 | 付 50 出狱金，**然后按这一掷移动**（不是原地不动） |
| 手上有出狱卡 | `card` 动作直接出狱，之后正常掷 |

命运牌 11 张，开局洗好放进 state，抽完自动重洗（`sealedDeck()`）。牌的效果有十种：移动（去某格 / 前进 / 后退）、进牢、出狱卡、收/付钱、每人给你 / 你给每人、按房屋层数付维修费。

`end` 阶段有个守卫：**本回合掷出过对子时拒绝 `end`**，必须先再掷一次。否则模型可以靠 `end` 把"再掷一次"的权利吞掉。

## 4. 终局

- **只剩一人**：`lastStanding()` → `finish(reason: "last_standing")`。
- **时钟到点**：身家最高者胜；并列则 `winner = "draw"`。身家 = 现金 + 地价 + 已盖房屋成本。
- **没有轮数上限**。来源把 20/40/0 轮做成游戏选项，这里按审计的结论先用生命周期时钟兜底（90 分钟），理由见 §7。

**投影只藏一样东西**：命运牌堆的剩余顺序。棋盘、现金、地契全是公开的，所以 `projectState` 只把 `deck` 置 `undefined` 并补一个 `deckCount`。MCP 全链路断言任何座位的视图都不含 `deck`。

`buildable` 是**按观看者下发**的：只在 `projectState` 里算当前 viewer 能盖房的格子。之前考虑过给每个座位各发一份数组，那样等于把每个人的现金状况间接广播出去（能盖房 ⇒ 有钱），改成按 viewer 就既省字段又不泄底。

紧凑决策态给模型的是**读得懂的一句话**而不是索引数组：`spaceLine()` 输出 `西窗 (13) · ¥220 · 墨 +2`，配上 `standOn`（你站哪儿）、`landed`（刚踩到什么）、`yourProperties`、`upgradeable`、`dice`、`doubles`。

## 6. 前端

```text
apps/web/src/game-ui/Monopoly.tsx    357 行
apps/web/src/game-ui/monopoly.css    155 行
```

**环的几何在前端**，和飞行棋自己管 52 格一样：服务端只存索引，浏览器决定它画在哪。`cellOf(index)` 把 24 格排进 7×7 的方框，起点在右下角、顺时针，和印出来的棋盘读法一致。

前端**不判断规则**。能盖哪些格子来自 `buildable`，能按哪些按钮来自 `legalActions`，买地价格不做本地校验——把租金和垄断判定复制进浏览器，等于给"谁说了算"留了第二份会漂移的答案。

版面：顶部是各家现金胶囊（带出局/在牢/持卡徽章）→ 7×7 棋盘（格子上有组别色条、房价、房层数与棋子）→ 悬停格子的详情 → 骰子与提示 → 操作按钮。棋盘用 `mono-fit` 等比缩放，390px 宽的手机上不会溢出。
