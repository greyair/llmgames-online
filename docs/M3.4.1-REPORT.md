## 1. 结论

外部审查在 M3.4 里发现的两个问题都成立，且都不是设计问题，而是**接线**问题。两处均已修复，并各配一条会在修复前失败的测试。

| 编号 | 问题 | 是否成立 | 证据 | 处理 |
| --- | --- | --- | --- | --- |
| P1-a | Checkers `projectState` 未接入调用链，`positionCounts` 回到浏览器 | **成立** | 修复前 `browser()` 键列表含 `positionCounts`；迁移前 `CheckersRoom.ts:177` 明确剥离该字段 | 平台默认投影改为委托已注册插件 |
| P1-b | 终局写失败回滚后残留 `pendingMatchEnd` | **成立** | 回滚分支未清标记，`deliverPendingMatchEnd` 未校验 `status`；同一实例下一次成功动作广播 `game_ended` | 回滚清标记 + 投递前校验 + 时钟复位 |

审查未提到的第三种状态也一并处理：`stopTimers()` 在 `match_ended` 时被调用，回滚后定时器检查点留在 0，下一次 tick 会以 `now` 重新锚定，那段停机时间因此被豁免，**本应超时的回合不会再超时**。修复后检查点锚定在最后一次持久化写入时间，与 `clockSnapshot()` 的视图口径一致。

## 2. P1-a：公开投影只留一个出口

### 缺陷

`apps/workers/src/games/checkers/plugin.ts:271` 声明了 `projectState(state) → publicState(state)`，但 `BaseGameRoom.projectStateFor` 的默认实现是 `return state`，而 `CheckersRoom` 作为薄适配器没有覆写它。于是插件的投影**从未被调用**：

```
browser 视图（修复前）：… ,positionCounts,quietTurns,…   ← 内部簿记外泄
```

迁移前的 `CheckersRoom.ts:177-181` 是明确剥离该字段的，所以这是实打实的迁移回归。规则等价测试没抓到，因为金样本比对的是棋盘、子数、合法走法、拒绝文案——不含视图键集合。

### 修复

`BaseGameRoom.projectStateFor` 的默认实现改为委托规则模块（[BaseGameRoom.ts:3390](apps/workers/src/durable-objects/BaseGameRoom.ts)）：

```ts
protected projectStateFor(playerId: string, state: TState): object {
  const rules = this.gameRules();

  if (rules?.projectState) return rules.projectState(state, playerId);

  return state;
}
```

选择"平台默认委托"而不是"Checkers 适配器显式转发"，理由是这个方法的三个调用点（`buildClientView`、`buildAgentView`、`buildBroadcastView`）都是平台代码：让每个适配器自己记得转发一次，等于把同一个易漏点复制到未来每款游戏。未声明 `projectState` 的游戏（Connect4、Reversi）行为完全不变——`check:ai-spec` 无 diff 可以佐证公开 MCP 规格未变。

### 验收

`apps/workers/src/tests/platform/pluginProjection.test.ts`，5 条：

1. 对每款已迁移游戏（Connect4 / Reversi / Checkers），用**插件自己**算出生效的隐藏键集合，要求这些键在 browser / agent / replay 三种视图里都不存在；
2. 同一条用例里要求 `board` 仍在——否则"投影把一切删光"也会通过，测试就退化成摆设；
3. Checkers 的隐藏键集合必须**恰好**是 `["positionCounts"]`，保证上一条不是空集；
4. Checkers 三种视图的序列化结果不含 `positionCounts` 字样；
5. `/broadcast` 路由（推给所有旁观者 socket 的同一份 payload）不含该字段。

辅助改动：`tests/fixtures/game-room.ts` 的 `FixtureRoom` 增加 `rewatch()`，让回放视图可以被断言。

**验证测试本身有效**：把 `projectStateFor` 改回 `return state` 后，用例 1、3（Checkers 部分）失败，报错即 `expected { type: 'checkers', …(28) } to not have property "positionCounts"`。

## 3. P1-b：终局失败后的残留标记

### 缺陷

`applyGameEffects` 在规则返回 `match_ended` 时置 `pendingMatchEnd` 并停表；`saveAppliedAction` 写失败后只回滚 `gameState` 与幂等回执，标记留在原处。于是审查描述的场景真实存在：

1. 制胜一步 → 效果置 `pendingMatchEnd = "connect4"`；
2. 存储失败 → HTTP 500，状态回滚到 `playing`；
3. 同一实例继续服务；
4. 对手走一步无关的合法动作 → `dispatchAction` 末尾调用 `deliverPendingMatchEnd()`；
5. 广播 `game_ended{reason:"connect4"}`，而盘面还在进行中。

### 修复（三处，都很小）

```ts
// 1. 回滚路径：标记属于刚刚失败的那次写入，随回滚一起作废
this.pendingMatchEnd = null;
this.rearmTimersAfterRollback();

// 2. 投递前校验：没有终局状态就没有结果可播
if (this.gameState?.status !== "ended") {
  logEvent("match_end_dropped", { reason, roomType: this.gameState?.type });
  this.pendingMatchEnd = null;

  return;
}

// 3. 时钟复位：以最后一次持久化写入为锚，而不是 now
private rearmTimersAfterRollback(): void {
  if (!this.gameState || this.gameState.status !== "playing") return;

  this.lastGameTimerTickAt = this.gameState.updatedAt;
  this.lastTurnTimerTickAt = this.gameState.updatedAt;
  this.timerTurnStartedAt = this.gameState.turnState.startedAt;
}
```

第 2 条是行为修复，第 1 条是卫生措施（避免标记活到下一个 `flushPendingMatchEnd` 调用点），第 3 条修的是审查里"检查停表后的时钟恢复"这一项：锚定 `now` 会把停机窗口当作不存在，锚定 `updatedAt` 则与 `clockSnapshot()` 的展示口径一致，两者不再漂移。

### 验收

`BaseGameRoom.matchEnd.test.ts` 从 2 条扩到 4 条，新增两条（都在同一实例内完成，不重建 DO）：

- `keeps the clock running after a rolled-back result`：制胜步写失败 → 时间推进 40s（回合 30s）→ `alarm()` → 回合编号必须增加、状态仍 `playing`。修复前该用例读到 `expected 7 to be greater than 7`（定时器被留在停止状态）。
- `does not announce a rolled-back result on a later action`：写失败 → 解除故障 → 当前玩家走一步非终局动作 → 返回 200、状态 `playing`、`winner` 为 `null`，且**没有任何** `game_ended` 被广播。修复前该用例读到 `expected [ 'connect4' ] to deeply equal []`。

为了观测广播，测试子类覆写 `broadcastProjected` 记录 `game_ended` 的 `reason`，再调用 `super`。

## 4. 关于"公开状态等价"这项通用能力（P2）

审查的建议是把玩家投影、Agent 投影、回放投影分别作为独立验收项。已按此落地为**行为级**、与具体游戏无关的测试：不比对"投影函数返回什么"，而比对"客户端能读到什么"。这样下一个游戏（Battleship 有私有舰队、Codenames 有队长词卡）只要在插件里声明 `projectState`，同一份测试就会自动覆盖它，不需要为新游戏再写一份。

覆盖矩阵：

| 出口 | 生产者 | 是否被本测试覆盖 |
| --- | --- | --- |
| 浏览器视图（`/state`、`/agent/view` 之外的客户端读取） | `buildClientView` → `projectStateFor` | ✅ |
| WebSocket `state` 帧 | `broadcastState` 逐 session 调 `buildClientView` | ✅（同一份 payload） |
| WebSocket `/broadcast` 旁观帧 | `buildBroadcastView` → `projectStateFor` + `broadcastProjection` 白名单 | ✅ |
| Agent 视图（MCP `get_state` / `wait_for_turn`） | `buildAgentView` → `projectStateFor` | ✅ |
| 回放帧 | `buildRewatchView` → 插件 `rewatchView` | ✅ |

`/broadcast` 另有一层 `broadcastProjection` 白名单，因此这条用例在修复前也是绿的——它守的是"两层都不能开始转发内部簿记"，不是为了证明本次缺陷。
