# M4.2 — 飞行棋（Aeroplane Chess）

- **基线**：M4.1 收尾（`ffee1d9` 审计提交之上）
- **来源**：West Window `06e4b75` `packages/engine/src/games/aeroplane*.ts`（MIT, `Copyright (c) 2026 SerenQi`）
- **结论**：M4.1 的样板复现了一遍——第二款游戏仍然没有动 `contract.ts` 和 `BaseGameRoom`。这一关要验证的是 M4.1 没有碰的东西：**同一次已接受行动里的随机数**。

## 1. 规则

2–4 人，每人 4 架同色飞机。进度是**一个整数**，所有规则都写在它上面：

```text
 -1      机场（hangar）
  0      起飞点
  1..52   环形航线第 p 格，全局格号 g = (13c + p - 1) mod 52
 53..58   跑道第 1..6 格
 59      中心点（到位）
```

四条特殊规则：

| 规则 | 表现 |
| --- | --- |
| 起飞 | 只有 6 点能让飞机出机场；出机场后再掷一次 |
| 同色跳 | 落在**自己颜色**的格子上（`p % 4 === 0`，`p ≠ 52`）再前进 4 格 |
| 直飞 | 自己的第 20 格飞到第 32 格 |
| 撞回 | 落点上有别家飞机，全部退回机场 |
| 弹回 | 超过中心点要按多出的步数弹回，所以进屋必须正好 |
| 三个 6 | 同一回合连续掷出三个 6，被选中的飞机退回机场 |
| 终局 | 四架飞机全部到中心点，`match_ended reason=all_planes_home` |

行动只有两种形状：

```text
roll                    掷骰
launch_plane { plane: 1-4 }   机场 → 起飞点
move_plane   { plane: 1-4 }   沿航线/跑道前进一步
```

`turnActions` 只在两种都合法时才同时给出 `launch_plane` 和 `move_plane`——所以按 `legalActions` 点飞机的客户端，永远不会发出会被拒的意图。

## 2. 骰子的三条不变量

这是 M4.2 真正要证明的东西。点数在 **`applyAction` 内部**用平台 CSPRNG 生成并写进状态：

```ts
const value = randomInt(6) + 1;   // lib/csprng.ts，rejection sampling，不用 Math.random
state.roll = value;
state.rollBy = playerId;
```

由此得到三条性质，每条都有测试：

1. **客户端不可伪造**——行动数据里没有点数位，`roll` 也不接受任何参数。
2. **同一次已接受行动重试不重掷**——平台在重复 `requestId` 时回放已记录的事件，不会再次进入 `applyAction`；测试里连发两次同一 `requestId`，`state.roll` 保持不变。
3. **DO 重启不改点数**——`roll` 是状态的一部分（不是内存变量），重启后从 `storage` 读回同一个值；测试在掷出后重建房间再读。

`onTurnTimeout` 是"丢掉这一次投掷"：清空 `roll`/`rollBy`/`sixes`，棋盘一格不动，交棒给下一家。它**不会**替玩家随机走一步——超时不该产生玩家没做的决定。

## 3. 后端

```text
apps/workers/src/games/aeroplane/board.ts    92 行   进度常量、格号换算、颜色分配、所在区段
apps/workers/src/games/aeroplane/rules.ts   208 行   planAeroplaneMove（唯一判定入口）、撞回、跳/飞
apps/workers/src/games/aeroplane/plugin.ts  415 行   状态、掷骰、落子、终局、超时、agentFields
apps/workers/src/games/aeroplane/agent.ts   134 行   紧凑决策态
apps/workers/src/durable-objects/AeroplaneRoom.ts 112 行  平台胶水（同 GomokuRoom）
```

`planAeroplaneMove(table, seat, plane, roll)` 返回**要么完整的后果、要么拒绝的理由**。一个函数同时服务三件事：校验意图、列合法选择、给模型算好"这一步会怎样"，所以规则只有一份。跳跃链的约束（一次跳 + 一次飞，绝不两次）也只在它里面表达。

紧凑决策态（`agentFields` + `agentDecision`）给模型的东西：

```text
boards[seat][plane-1]   进度数字（4 座 × 4 架）
seats                   0:red / 2:blue …
home[seat]              已到位架数
takeoff / roll / sixes
racesTo: 59
moves                   "move 3 → sq17 jump capture blue 2"  —— 后果预先算好
```

最后一行是重点：模型最容易算错的就是"落在自己颜色上还要再跳 4 格"，所以 `moves` 里直接写出跳、飞、弹回、撞回谁。骰子本身也在 `roll` 里，模型不需要自己维护。

## 5. 前端

```text
apps/web/src/game-ui/Aeroplane.tsx   655 行  15×15 十字棋盘（52 格航线 + 4 条跑道 + 4 个机场 + 骰子）
apps/web/src/game-ui/aeroplane.css    80 行  container query 自适应
apps/web/src/design/tokens.css        13 个 --palette-aero-* 令牌
apps/web/src/design/games.css         [data-game="aeroplane"] 三个色槽
apps/web/src/interface/GameMark.tsx   10×10 像素字模
apps/web/src/interface/GameScene.tsx  96×64 场景（十字 + 三色航线 + 两架飞机）
```

**棋盘几何**是这次唯一需要设计的东西。来源只存进度数字，不存坐标，所以 52 格到屏幕的映射由前端拥有，并且必须满足一条硬约束：

```text
12 段 3,5,6,2,5,5 | 3,5,6,2,5,5   = 52
```

十字每条臂 3 格宽、6 格长，轮廓正好 52 格；四个凹角是斜向相邻（这是真实飞行棋盘的样子）。选这个几何不是为了好看，是因为它让**每 4 格一个颜色**、**每条臂端正好是某色的入跑道口**、**90° 旋转把颜色 c 的弧段映射到 c+1** 三件事同时成立——测试里用 `LOOP[13c]`、`LOOP[13c+51]` 与跑道首格相邻来固定这些不变量。

**一处刻意的规则复制**：`landingFor(from, roll)` 是"这一掷会把它送到哪"的镜像，只用来画悬停虚影。它会漂移，所以注释写明它只影响虚影、不影响任何判定；骰子和落点仍然只信服务端。没有把它抽成共享包，是因为那需要让浏览器依赖 workers 的规则模块，代价大于收益。

交互：`legalActions` 里有点飞机才让点，机场里的飞机在 `launch_plane` 合法时才可选——客户端不重新推导"6 点才能起飞"。掷骰按钮只在 `roll` 合法时出现，掷完变成提示文案。

文案：`game.aeroplane.*` 五键（中英）+ `board.aeroplane*` 七键 + 规则七条（两版）+ 房间说明。

## 6. 与来源的差异

| 项 | 来源 | 这里 | 原因 |
| --- | --- | --- | --- |
| 输入 | 图形点击 | `{ plane: 1-4 }` + `roll` | 平台要求可校验、可发现 |
| 掷骰 | 客户端动画 | 服务端 CSPRNG，结果进状态 | 可伪造的骰子等于没有骰子 |
| 座位颜色 | 固定四色 | 2 人取对角（red/blue），3 人取三色 | 两人局也要满盘 |
| 座位数 | 2–4 | 2–4 | 同 |
| 坐标 | 无（只有进度） | 同，屏幕坐标留在浏览器 | 服务端不画图，52 个坐标过网没有价值 |
| 机器人 | `aeroplaneBot` | 未移植 | 平台不托管 bot |
| 悔棋/托管 | 无 | 无 | 平台没有 undo 语义 |
