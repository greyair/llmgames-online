# M3.7 — Contexto 迁移与「无回合」并发验证

- **基线**：`7d13dc1`（M3.6 完成 + MCP 全链路参数化）
- **范围**：仅迁移 Contexto，不改协议、不加新钩子（一处契约扩展见 §3）
- **结论**：迁移完成，既有 13 个行为用例与新增 MCP 全链路用例全部通过

## 1. 结论

Contexto 是第一款**完全没有回合顺序**的游戏：`turnState.currentPlayerId` 全程为 `null`，每个座位在自己的时钟上猜词，最多 50 次，先猜中者胜。这正好检验 M3 契约里最容易出问题的一条假设——"平台总有一个当前玩家"。

结果如 M3 设计预测：**不需要任何新钩子**。`mayActNow` 已经能表达"每个有余量的座位现在都可以行动"，平台的 `isYourTurn`、`wait_for_turn`、`legalActions` 三条路径都自动跟着走。这也是把 Contexto 排在 Pokémon/Poker 之前的理由：它是"轻量游戏接入成本"的样本。

迁移后 `ContextoRoom.ts` 从 **291 行降到 116 行**，规则全部进了 `games/contexto/`。

适配器只做四件事：把 `createDefaultState` / `onStartGame` / `getLegalActions` / `handleGameAction` 转给插件，外加超时钩子的接线。**没有** `projectStateFor`、`buildRewatchView`、`buildYouContext` 的覆写——这三处以前是手写投影，现在由 `projectState` / `rewatchView` / `mayActNow` 统一接管，浏览器视图、WebSocket 广播、MCP 决策态读同一份。

## 3. 一处契约扩展：`persist`

Contexto 有一个历史行为与新契约冲突：**词不在词典里时，服务端返回 400，但同时把这次尝试写进 `progress.lastAttempt`**，好让客户端在输入框旁标出 "not in pool"。

契约原本写着"拒绝不得改变状态"。有两种做法：

- 把它当成功处理（200）：客户端行为不变，但 agent 会把"词不在词典"读成一次有效行动，属于协议变更；
- 保留 400，同时允许插件声明"这次拒绝要落盘"。

选了后者，`GameActionResult` 的失败分支新增可选 `persist`：

```ts
| { ok: false; message: string; persist?: boolean }
```

适配器在返回消息前执行 `saveState()` + `broadcastState()`。影响面只有 Contexto 一个动作；其余四款游戏的拒绝仍是纯函数、状态不动。

## 5. 剩余风险

1. **`progress` 的掩码依赖空串约定**。`projectState(state, "")` 被平台当作"公开广播/归档"的入口，Contexto 靠它决定是否下沉完整词表。这层语义写在 `rules.ts` 的注释里，但没有类型约束；若将来有游戏误用空串，会把私有词漏进广播。
2. **`persist` 是逃生口**。它让"拒绝时写状态"合法化，但只有 Contexto 用。若第二款游戏也想这么做，应先考虑把"记一次无效尝试"建模成正常动作（返回 ok + 无事件），而不是继续扩散 `persist`。
3. **回放是全量揭示**。`rewatchView` 用 `projectState("", state)`，归档里含每个座位的全部词与秘密答案，符合"回放全量揭示"的约定，但归档文档需要写清这一点。
4. **共享时钟**：`timerConfig.turnTime === gameTotalTime`，`onTurnTimeout` 只是重置余量。这是历史行为（Contexto 没有回合），但意味着"回合超时"在这款游戏里没有实际约束力。
