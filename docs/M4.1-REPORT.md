## 1. 规则

自由五子棋，15×15，黑先，**五子或更多连成一条线即胜**（长连算赢），225 点占满未连成五子为和局。

从来源搬过来的判定是"穿过落点的最长连线 ≥5"，而不是"恰好五子"——后者会悄悄判负长连。落子、换手、终局、事件与归档形状：

```text
place_stone { row: 0–14, col: 0–14 }   零基，行从上、列从左
非法：越界 → 400，占用/非本方回合 → 409
终局：match_ended reason=five_in_a_row / draw
状态：board[15][15]、seats、winner、lastMove、winLine
```

`winLine` 存整条连线（不止五子），前端据此画胜利线。

## 2. 后端

```text
apps/workers/src/games/gomoku/rules.ts      160 行  几何、连线、威胁点、投影棋盘 schema
apps/workers/src/games/gomoku/plugin.ts     190 行  状态、行动、终局、agentFields
apps/workers/src/games/gomoku/agent.ts       56 行  紧凑决策态
apps/workers/src/durable-objects/GomokuRoom.ts 99 行  平台胶水（照 Connect4Room）
```

紧凑决策态做了两件对模型有意义的事：

- 棋盘从 15×15 的嵌套数字压成 15 行数字串（`"000…"`），省掉 225 组括号；
- 预计算 `winningMoves` / `blockingMoves`（按 GTP 风格标签，如 `E8`），模型不用每回合重扫 225 个点。空点可从棋盘推导，不再重复列出。

## 5. 平台通用文件改了多少（M4 的核心问题）

| 类别 | 文件数 | 性质 |
| --- | --- | --- |
| 契约与房间内核（`contract.ts`、`BaseGameRoom.ts`） | 0 | **零改动** |
| 编译器强制的登记面（`Record<GameTypeId,…>` 的六处） | 6 | 加一行，漏了编译不过 |
| 部署面（wrangler ×2、migration、schema、Env、路由、导出） | 6 | 机械追加 |
| 手写数组 / 按游戏分支 | 5 | 见下 |
| 前端登记（棋盘表、目录、图标、插画、i18n、规则、预览、e2e） | 9 | 机械追加 |

那 5 处"按游戏分支"值得点名，它们是这次唯一需要判断的地方：

1. `Room.tsx` 的 1v1 帮助文案列表——五子棋是双人局，必须加进去，否则显示团队文案。
2. `MatchDesk.tsx` 的"显示棋子色"与"座位号来源"两处列表——不加则玩家卡片不显示黑白。
3. `FinalState.tsx` 的终局棋盘分支——不加则结算页没有棋盘。
4. `broadcastProjection.ts` 的公开直播棋盘白名单——不加则直播看不到棋盘。

这四处都是**同一类东西**：平台需要知道"这款游戏有没有棋盘、是不是座位制"。M4.6 之前应该把它们收成一个由 manifest 声明的能力位（`boardKind`、`seatBased`），而不是继续加 `includes(...)`。现在不改，是因为只服务一款新游戏时抽象没有第二个样本可验证——把它记进 M4.6 的清单。

## 8. 与来源的差异（明确的不等价）

| 项 | 来源 | 这里 | 原因 |
| --- | --- | --- | --- |
| 输入 | 文本 `"H8"` | 结构化 `{row,col}` | 平台要求可校验、可发现 |
| 坐标标签 | GTP（A–P 跳 I、行从底数） | 行动用零基，标签仍按 GTP 输出 | 让读过来源规则的模型不用换算 |
| 棋盘尺寸 | 固定 15 | 固定 15 | 来源也只支持 15，不加无意义选项 |
| 机器人 | `gomokuBot` 启发式 | 未移植 | 平台不托管 bot；留给 Agent Runner |
| 禁手/连珠 | 无（自由规则） | 同 | 保持自由规则，长连算胜 |
| 悔棋 | 无 | 无 | 平台没有 undo 语义 |
