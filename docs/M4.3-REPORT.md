## 1. 一张共用的牌

两款游戏共享一副牌和"压过上一手"的判定，但合法牌型不同。放进同一层比复制两份近似代码更省事：

```text
apps/workers/src/games/cards/deck.ts     226 行  牌面编解码、rank 阶梯、洗牌、按 rank 选牌
apps/workers/src/games/cards/combo.ts    204 行  牌型识别 + 比较 + 描述
apps/workers/src/games/cards/moves.ts    227 行  合法出牌枚举（两款共用）
```

一个 `classify(cards, rules)` 认全 14 种牌型，`ComboRules` 决定这局游戏是否承认它：

| 旗标 | 跑得快 | 斗地主 |
| --- | --- | --- |
| `rocket`（双王） | ✗ | ✓ |
| `fourWithWings`（四带二 / 四带两对） | ✗ | ✓ |
| `minPairRun`（连对最短） | 2 | 3 |
| `bareTripleFinishes`（裸三张只能收尾） | ✓ | ✗ |

比较只有一条规则：**火箭 > 炸弹 > 同型同张数比 key**。

牌面用文本 id：`S3`、`HT`、`DJ`，双王是 `j1` / `j2`。这里有一个真实踩坑：

> 双王最初写成 `SJ` / `BJ` 当标签，而 ♠J 的牌号正是 `SJ`。牌号解析器把黑桃 J 认成小王，一手正常的牌被判成"你手上没有小王"。MCP 全链路测试第一次跑就撞上了。现在王的**任何**表示都不带花色字母：id `j1`/`j2`，标签 `J1`/`J2`。

## 2. 跑得快

48 张牌（无王、去掉 ♥2 ♣2 ♦2 与 ♠A）。三人局 48 张全发、每人 16；二人局每人 16、另 16 张作废。

```text
play_cards { cards: ["S3","H3"] }   出牌，支持只写 rank（"3 3"，服务端挑最小花色）
pass                                不要
```

三条容易写错的规则，都有测试：

1. **三张只能当最后一手**。领出阶段出裸三张要被拒；`legalMoves` 也不把它列进提示，所以模型和超时兜底都不会撞墙。
2. **领出不能不要**。`turnActions` 在领出时只给 `play_cards`。
3. **一轮结束是"自上次出牌后其余人都不要"**。计数在每次出牌时清零，不是每轮清零——写成每轮清零会让第二个不要的人提前收下一轮。

超时：跟牌时按"不要"处理；领出时不能不要，于是服务端打出**手上最小的一手**并发 `turn_timeout`。这是替玩家做的决定，但确定性、最小，总比牌桌卡死好。

## 3. 斗地主

54 张牌（含大小王），三人，每人 17 张 + 3 张底牌。阶段是 `bid → play`。

```text
bid { value: 0-3 }                  叫分；0 = 不叫
play_cards { cards: [...] }         出牌
pass                                不要
```

**叫分**：三家依次叫 1/2/3（必须高于当前分）或不叫。叫 3 立刻结束；三家都不叫则重新发牌，由下一个座位先叫。最高者成为地主，拿走三张底牌（此后公开）并先出。

**一打二**：这是本阶段唯一一处公开接口变更。

| 位置 | 变更 | 原因 |
| --- | --- | --- |
| `ClientView.winnerTeam` | `"red" \| "blue"` → `string` | 胜负是阵营，不是座位 |
| `ClientView.you.team` | 同上 | 让两个农民都看到"我们赢了" |
| `MatchResult` | 新增 `teamLabel()`，未知值原样显示 | 文案映射不能写死两种颜色 |
| i18n | `match.teamLandlord` / `match.teamFarmers` | 中英各一条 |

`you.team` 走的是已有的 `youFields` 钩子（Codenames 早年用过同一个口子），所以**契约本身没有新增钩子**，只是把两个字段的类型放宽。

**计分**：`叫分 × 2^(炸弹+火箭) × 春天`，地主赢为正、农民赢为负。一局一终局，所以 `score` 只是这手牌的分数，不做跨局累计——来源的 1/3/6 局赛制没有搬，因为平台的一次 match 只有一个结局，硬塞多局要么改终局语义、要么加房间配置项，两者都不划算。这条差异记在 §6。

`classify` 里还有一条容易被忽略的规则：**两张王只能当王炸**。任意带牌的牌型如果翼牌同时包含大小王，一律拒绝——否则"飞机带两张王"会被判成合法。

版面从上到下：对手剩牌胶囊（斗地主还带地主徽章与叫分）→ 牌桌（底牌、桌面/上一轮）→ 手牌 → 提示与按钮。

**一个刻意的取舍**：前端**不判断牌型**。选中任意张就能按"出牌"，判定和拒绝信息来自服务端。把 14 种牌型的分类器复制到浏览器，等于给"谁决定胜负"留了第二份会漂移的答案。唯一在本地做判断的是叫分按钮的"是否高于当前分"——那是一个整数比较，不是规则。

手牌布局按宽度两套：宽屏一行不折行（放不下就横向滚动，隐藏滚动条），≤560px 换成更小的牌折成两排。手机上一行塞 16–20 张牌，要么重叠到看不清点数、要么滚出屏幕——那都是玩家会忘记自己有哪些牌的理由。

## 7. 与来源的差异

| 项 | 来源 | 这里 | 原因 |
| --- | --- | --- | --- |
| 输入 | 文本 `"3 3 4 4"` | `{ cards: [...] }`，支持只写 rank | 平台要求可校验、可发现 |
| 洗牌/发牌 | `ctx.seed` 派生 | CSPRNG + Fisher–Yates，结果进状态 | 不可预测且可重放 |
| 超时 | 客户端自律 | 跟牌=不要，领出=最小一手，叫分=不叫 | 无超时会让牌桌永久卡住 |
| 斗地主局数 | 1/3/6 局累计 | 一局一终局 | 平台一次 match 只有一个结局 |
| 反春天 | 计入 | 未实现 | 需要单独跟踪地主首手，记录在案 |
| 机器人 | `paodekuaiBot` / `doudizhuBot` | 未移植 | 平台不托管 bot |
